New in 3.0

The framework stopped writing your code.

In 3.0, people and agents write the application code, and the framework no longer generates it. What the generator used to write is now a small, explicit contract that is safe to write by hand. The project's state can be read as data: in the admin, in the Setup Wizard, and from a CLI.

Where does the name Magrathea come from?

In Douglas Adams' The Hitchhiker's Guide to the Galaxy, Magrathea is an ancient planet whose engineers built custom luxury planets for the galaxy's wealthiest beings. Their most famous creation was Earth, a supercomputer designed to calculate the Ultimate Question of Life, the Universe, and Everything.

"The Magratheans built planets to order. MagratheaPHP gives you the tools to build yours, without waiting 5,000,000 years for the order to complete."

What's in the box

The pillars of Magrathea

Everything a web application needs, with a short dependency list.

hub

An ORM you can read

Models are a handful of properties and Controls are one line. You get GetAll, GetWhere, a fluent Query builder, pagination, transactions and streaming queries, plus strict types that return ints as ints.

api

REST API with JWT

Routes with :name parameters, five CRUD routes from one Crud() call, CORS from a list or a file, JWT login and refresh, and response caching.

dashboard

An admin panel

Users, app settings, cache, CORS origins, logs, an API explorer, CRUD pages for your own models, and a full Database section, all behind CSRF-protected forms.

terminal

A CLI for people and agents

vendor/bin/magrathea runs checks, describes the schema, runs queries, dumps and imports, and manages admin users. It prints text or JSON, with clear exit codes.

tune

Environments in one INI file

[dev] and [production] live side by side, secrets come from $=ENV_VARS, and Dev(), Debug() and Prod() decide what gets shown and what gets logged.

inventory_2

Batteries, not bloat

SMTP mail, a logger, a debugger, a file cache, CSS/SCSS and JS compressors and UUID v7, built on a handful of trusted packages: PHPMailer, php-jwt and scssphp.

Made for the age of agents

Your agent writes the code. Magrathea checks it.

Generated code is code nobody reads. In 3.0, an agent writes small classes from a precise manual and then checks its work against the real database, without ever opening a browser.

  • menu_bookThe manual ships with the package. skills.MD (the cookbook) and docs/mds/ (the reference) land in vendor/, kept in sync with the source.
  • data_objectOne JSON document per command. With --json, stdout is always a single document, errors included.
  • front_handNo prompts: the flag is the consent. Writes refuse to run without --write or --yes, and nothing connects before that check.
  • pinExit codes you can branch on: 0 ok, 1 an ERROR finding, 2 a usage error.

infoMethod

PHP 8.3 + Apache (mod_php) with OPcache. Each framework ran in its own Docker container, capped at 1 vCPU / 512MB RAM. Laravel and Symfony ran in production mode with cached config and routes. Load came from wrk (2 threads, 50 connections, 30s runs after a 5s warmup) against two JSON endpoints, a minimal object and a 5-object list, with no database. Memory was measured with memory_get_peak_usage(). CPU/req = 1000 ÷ req/s on one vCPU.
